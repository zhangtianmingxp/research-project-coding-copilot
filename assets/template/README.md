# Research Project

本仓库使用 Research Project Coding Copilot 管理科研代码开发轮次。

## 开始

1. 填写或替换 `project_plan.md`。
2. 在 Codex 中调用 `$research-project-coding-copilot`。
3. 使用下面的短指令推进项目。

`project_plan.md` 是正式轮次的必要输入。用户可以自己填写，也可以把研究想法告诉 AI：

```text
$research-project-coding-copilot 生成项目计划书：研究问题是……；已有数据是……；希望最终完成……
```

已有工作项目可以使用：

```text
$research-project-coding-copilot 整理项目计划书：结合当前仓库内容和我的补充理解，已经完成……，接下来希望……
```

用户审查并修正计划书后，才能生成正式的下一轮 prompt。

计划书只详细展开当前活动 Gate。后续未解锁路线各写一句，获得上游 GO 后再展开；不提前写完整 Prompt5-Prompt11。约 300 个非空行或 20 KB 只是上下文范围提醒，不是科学硬门槛。

```text
生成下一轮
执行当前轮
生成下一轮
```

不需要重复说明“不要执行”或“不要生成下一轮”。skill 已经为每条指令规定了停止位置。

默认推进策略是尽早设计模型、尽早运行有科研辨别力的实验并尽早作出 GO/PIVOT/STOP/INCONCLUSIVE 决策。探索路线可以先使用清晰、可追踪的脚本或 notebook；只有得到证据支持的论文关键路径才进入系统工程化。一个工程问题经过一次聚焦修复仍未解除时，应优先绕过、简化或换路线，不连续多轮深挖。

启动后继版本前，先运行项目组合与成果收割 Gate：`WRITE_NOW` 表示最低可发表证据已经成立，应冻结新实验并完成投稿；`ONE_DECISIVE_EXPERIMENT` 只允许一个能改变投稿判断的实验；`HOLD` 暂不投入；`STOP` 关闭项目族。它只做有界只读审计并输出一张表，不新增 registry，也不在普通轮次反复运行。

复用同一数据、outcome 和核心问题的 v1/v2/v8 等版本属于同一项目族。启动后继版本前先使用“新版本审计”提取前序 STOP 的根本 blocker；换模型、阈值、亚组或版本名本身不是新证据。只有新增独立数据、测量分辨率、真正不同的 estimand、正交证据或独立先验假设，才可能得到新版本 GO。重复 STOP 后默认止损，根本 blocker 仍记录在唯一的 `paper_map.md`。

生信 assay 和处理结果默认带有测量误差，不作为无误差的生物学真值。判据优先采用严格匹配后的同行相对表现和不确定性；新任务没有 benchmark 时使用简单基线、null/负对照、稳定性及生物学/正交一致性，不强设通用绝对指标。与同行持平可以支持路线可行，但论文创新仍需其他贡献。

每次正式生成 prompt 或 result 前，AI 会先形成不发布的内稿，分别检查科学逻辑和可执行性/事实证据，修改并复查后才写入单一正式文件。内稿不另存为历史文件；存在无法消除的关键歧义时不会发布半成品。

## 常用指令

| 指令 | 行为 |
| --- | --- |
| `状态` | 检查当前轮次和下一步 |
| `生成项目计划书：...` | 根据研究想法生成或完善计划书 |
| `整理项目计划书：...` | 结合已有仓库和用户理解整理计划书 |
| `项目组合审计：<目录...>` | 将指定范围的项目族分为 WRITE_NOW / ONE_DECISIVE_EXPERIMENT / HOLD / STOP |
| `成果收割审计` | 审计当前项目族及可识别相邻版本 |
| `新版本审计` | 先做成果收割 Gate；仅对 ONE_DECISIVE_EXPERIMENT 审计前序 blocker |
| `快速验证：...` | 用一个决定性比较快速判断一个 claim，最多 1-3 轮 |
| `继续快速验证` | 上一轮为 INCONCLUSIVE 时继续一轮，最多到第 3 轮 |
| `生成下一轮` | 生成下一轮 prompt，然后等待审查 |
| `执行当前轮` | 执行当前 prompt，完成必要有效性检查并生成对应 result |
| `继续 N 轮` | 连续生成并执行 N 轮，然后停止 |

详细科研工程规则见 `PROJECT_RULES.md`，工作流状态见 `.research_agent/project_state.md`，每轮记录保存在 `ans_qes/`。论文 claim 的轻量证据状态只记录在 `paper_map.md`。
