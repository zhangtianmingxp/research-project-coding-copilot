# 科研项目计划书模板

> 本文件是生成正式 `promptN` 的必要输入。请由用户自行填写，或使用“生成项目计划书：研究想法……”让 AI 生成初稿。已有项目可以使用“整理项目计划书：用户理解和目标……”，让 AI 结合仓库已有代码、文档和结果整理。用户审查确认后再开始正式轮次。
>
> 计划书只详细展开当前正在决策的 Gate。尚未被结果解锁的后续路线各用一句话记录，获得 GO 后再展开。建议控制在约 300 个非空行或 20 KB 内；这是上下文范围提醒，不是科学验收阈值。

## 一、项目名称

请填写项目名称。

## 二、研究背景与意义

说明研究领域、已有工作、当前空白、为什么这个问题值得研究，以及最终希望支撑的论文方向。

## 三、项目组合、成果收割与前序版本审计

若是全新项目且不是后继版本，写“不适用”。若准备复用同一数据、outcome 或核心问题建立新版本，先对项目组合做轻量成果收割 Gate，并记录当前项目族：

- **审计范围**：待填写项目组合根目录或当前项目族。
- **最小可发表单元**：待填写一个边界清楚的 claim、决定性证据和目标图表。
- **最强现有证据**：待填写决策级结果或稿件证据。
- **关键缺口**：待填写会影响结论有效性或投稿判断的缺口。
- **Gate**：`WRITE_NOW / ONE_DECISIVE_EXPERIMENT / HOLD / STOP`。
- **现实投稿范围与动作**：待填写；CNS 目标不得阻断一个证据成立的边界清楚论文。

`WRITE_NOW` 冻结新实验并转入投稿；`ONE_DECISIVE_EXPERIMENT` 只允许一个能够改变投稿判断的实验；`HOLD` 暂不投入；`STOP` 关闭项目族。只有 `ONE_DECISIVE_EXPERIMENT` 才继续填写后继版本审计，而且应优先在当前仓库完成该实验：

| 前序版本/路线 | 数据与 outcome | 终局决定 | 根本 blocker | 本版本新增的可识别信息 |
| --- | --- | --- | --- | --- |
| 无或待填写 | 待填写 | GO / PIVOT / STOP / INCONCLUSIVE | 待填写 | 新数据、独立样本、测量分辨率、正交证据或独立先验假设 |

说明本版本为什么不是仅更换模型、特征表示、阈值、seed、metric、亚组或版本号。相同根本 blocker 已导致两个版本 STOP，或同一数据/outcome 项目族已连续三个版本 STOP 时，必须先给出项目族 `GO / PIVOT / STOP / INCONCLUSIVE`；不是 GO 就不得启动新版本。四类成果收割 Gate 是资源分配动作，不等同于这里的科学决定。

## 四、核心科学问题

1. 问题一。
2. 问题二。
3. 问题三。

## 五、总体目标

描述项目最终要产出的代码、数据处理流程、实验结果、图表、benchmark、论文结论或软件工具。

## 六、论文定位与核心证据链

说明目标论文层级或参照标准、核心 novelty、候选主结论、每条结论所需的关键 figure/table、机制证据、稳健性验证和外部验证。若以 CNS 或其子刊为目标，应明确哪些证据体现广泛意义、机制深度和跨数据泛化；目标期刊只是质量参照，不代表录用保证。

## 七、数据来源与研究对象

列出主要数据、外部验证数据、数据版本、数据规模、下载或访问方式，以及本地大文件的存储和上下文隔离规则。

## 八、任务定义

说明输入、输出、预测任务、统计任务、实验任务或建模任务。

## 九、当前活动 Gate

只详细填写当前 Gate：

- **当前 claim / 科学决策**：待填写。
- **决定性比较**：待填写简单基线、候选方法和公平比较条件。
- **最低决策级规模**：待填写 cells / patients / cohorts / genes / chromosomes / replicates、独立实验单位及依据。
- **判据**：待填写 GO / PIVOT / STOP / INCONCLUSIVE；判据应匹配 assay 噪声、同行 benchmark 和不确定性。
- **产物**：待填写结果表、图、配置、命令或必要代码。
- **立即分支**：GO 后升级哪项证据；PIVOT 改什么；STOP 关闭哪个 claim；INCONCLUSIVE 只补哪一项信息。

尚未解锁的后续 Gates 每项只写一句话，不提前设计 Prompt5-Prompt11 或完整实现细节。

## 十、与证据阶段匹配的实现要求

说明探索阶段允许采用的最短可追踪实现、决策级实验所需的最低复现与有效性检查，以及路线进入 paper-grade 后才需要补充的模块边界、配置、测试、日志和文档。不得要求先完成通用工程框架再开始模型实验。

## 十一、实验层级、最低规模与验证标准

分别说明：

- 工程 smoke 可使用的最小输入，以及它只能验证什么；
- 能够比较方法或观察效应的最低科研规模，例如最低 cells / patients / cohorts / genes / chromosomes / replicates；
- 正式论文实验的全量规模、split、seed/replicate、统计检验、不确定性、外部验证和验收标准；
- 哪些情况下可以复用已有 smoke 并直接扩大，避免长期停留在低功效 pilot。
- target 属于哪种 assay 观测或派生标签、主要技术/处理误差、可能的 measurement ceiling，以及结论不能越过的真实生物学边界；
- 是否存在 dataset、split、输入和 metric 均可比的同行 benchmark。若存在，说明“超过或非劣于同行”的相对判据；若不存在，使用简单基线、null/负对照、重复稳定性、不确定性和生物学/正交一致性，不强设绝对分数线；
- 如果模型只与同行持平，论文价值还需要由哪项新任务、泛化、效率、解释性、机制或生物学发现支撑。

## 十二、限制与风险

记录数据、算力、依赖、实验设计、时间安排、论文审稿风险等。
